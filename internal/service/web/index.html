turn-state 注入

开启时只使用符合规则的 state。关闭后仍走本服务和所选出口，但不再采集、替换 state。

关闭注入不是绕过官方限流。401、403、429 的停止规则仍然生效；正在进行的回复不会被打断。

会话状态

CCS / CC Switch 与中转站

自动接管会检查当前选中的 Codex provider。官方走官方认证，中转走自己的 API key；不会把官方登录凭据拿去试中转站。

服务运行时别同时在 CCS 里切换同一份配置。检测到改动会停止接管流程，不强行覆盖你的新配置。先停服务，再切换，再启动。

使用 --no-config 启动时，此按钮不会修改 Codex 配置。

订阅与代理

选一种连接方式。

本地已经开着 Clash 一类工具，就填它的 HTTP 或 SOCKS5 地址。没有，也可以直接导入订阅。

端口以你的代理软件为准。此处填写的是地址，不是 PowerShell 命令。

有些订阅会按客户端返回不同内容。只有订阅提供方要求时再填写，不会伪装模型版本。

按订阅标签筛选，不是出口地理位置验证。需要跳过证书校验的节点不会被接受。

保存会替换本服务现有出口来源，并留下配置备份；不会修改你的代理软件、系统代理或订阅原文件。

路由

知道请求往哪走。

自动模式按顺序采集，state 和采集它的出口绑定。你也可以固定一个出口；切换后会重新采集，不会把旧票硬塞到新出口。

读取列表会重新获取订阅，但不调用模型。连接测试不带登录信息，也不消耗模型生成额度。

遇到问题

先看是哪一层没通。

本地 503：还没有合格 state

如果错误代码是 state_unavailable，说明服务没有拿到符合当前规则的票，不等于官方挂了。先看出口能否连接，再看会话状态。需要先正常用 Codex 时，可以主动关闭注入；程序不会偷偷帮你切换。

上游 503 / 502 / 超时

出口连接失败和上游拒绝不是同一回事。先测试你正在使用的出口，确认代理进程和端口。不要连点重试：真实请求可能已经执行，程序不会自动重发一次生成来赌成功。

unfinished config transaction

常见于直接关闭终端或系统异常退出。新版本会先核对文件：没被改动的旧接管配置可以安全恢复，再重新接管；如果 CCS 或你自己改过，保留备份和恢复记录，不覆盖新内容。

有代理地址，为什么还是直连？

旧版仅设置 CCODEX_PROXY 环境变量还不够，配置也要引用它。现在直接在「订阅与代理」选择代理、填地址并保存。当前服务不需要知道你以前在哪个终端设置过变量。

中转站为什么不能开启注入？

普通 Responses 中转未必提供官方 turn-state。此版本对中转采用不注入转发；不会拿官方账号去给中转打票，也不把一个 HTTP 200 宣称成改善了降智。

401 / 403 / 429

账号登录、访问权限或额度需要在 Codex / 服务提供方处理。管理面板不会用换出口来绕过这些限制。不要把 auth.json、订阅链接或完整日志发到群里。

只做 Astra。尝试改善使用体验，不保证消除降智或限流。

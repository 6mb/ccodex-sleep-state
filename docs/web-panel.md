# 管理面板：照着这条顺序用

第一次不用先研究参数表。把程序启动，填好出口，确认接管，再用一条短消息检查。遇到报错，面板应当告诉你是哪一步，不需要靠删配置碰运气。

## 先用最短的办法

1. 双击 `start.cmd` / `start.command`，或运行 `ccodex-sleep-state setup`。程序自动接入、打开浏览器并进入面板，已有配置不重置。
2. 看到已接管后，**重启 Codex、新建会话**，发一条短消息。旧任务不会被热切换。

正常启动不用再点接入按钮。首页的 **「一键接入 Codex」** 留给之后重新检查、修复和接入时使用。

自动接入会保留当前模型和注入开关，先备份配置；能安全处理的旧事务会按“保留当前配置”修复，复杂冲突仍请你选择。还没有配代理时，它仅检查本机 `127.0.0.1` 上的 7897、7890、10808 是否支持无需认证的 SOCKS5 握手；不会读取代理软件账号库或扫描外部网络。已经有代理、订阅或固定出口就继续沿用。

**首次 `setup` 没有明确兜底策略时采用“采不到合格 state 时先正常转发”；之前明确选过 `strict` 会保留。** 想严格等待，到「连接设置」选择。重新点首页接入按钮时，确认说明会明确选择普通转发兜底；它不是采集成功，也不解除官方限流。

程序用 60 秒内有效、仅可兑换一次的启动凭证免去复制口令；页面读取后立即从地址中清除。它不是把长期管理口令塞到 URL 中。若自动打开失败或凭证过期，按终端显示的管理地址和口令手动登录。默认地址是 [http://127.0.0.1:17841/admin/](http://127.0.0.1:17841/admin/)。口令和启动链接都不要转发。

面板和代理是同一个进程。关闭浏览器不会停止服务；退出仍用服务窗口的 Ctrl+C。

**已经能用了就不必继续研究下面的全部设置。** 需要填订阅、换模型、选 Team 或处理冲突时，再看对应小节。

## 没找到代理，手动选连接方式

「订阅与代理」里选择一种：

- **本地 / HTTP / SOCKS5 代理：**填实际代理地址。已经运行代理软件的，优先用这种方式。例如 `socks5://127.0.0.1:7897`，端口以你自己的软件为准。
- **订阅链接：**填完整 URL。远程要求 HTTPS；本机订阅接口可以用 `http://127.0.0.1:端口/路径`，不使用 `localhost` 或局域网 HTTP 地址。
- **本地订阅文件：**填本机文件的完整路径。程序只读取，不修改原文件。
- **直连：**仅在网络本身能访问所选上游时使用，不会自动继承其他软件的系统代理。

订阅还可以指定客户端标识、排除关键词和协议白名单。除非订阅提供方有要求，客户端标识留空即可。名称里写英国不等于程序已经验证了出口在英国；关键词过滤只是过滤订阅标签。

### 两种测试有什么区别

| 操作 | 做了什么 | 没有证明什么 |
| --- | --- | --- |
| 先测试能否读取 | 读取或下载来源、解析并构建出站 | 不证明节点可连通，也不调用模型 |
| 保存并应用 | 备份旧配置，替换本服务的来源 | 不修改代理软件、系统代理或原订阅文件 |
| 路由里的连接测试 | 用指定出口请求上游，不带模型登录凭据 | 不证明账号权限、模型质量或能采到 state |

来源测试成功后还要保存，测试不会替你保存。保存会替换整组来源，不是无限往旧列表追加。切换时若有请求执行或账号处于上游拒绝/限流状态，程序会提示等待，而不是中途强换。

## 需要时再选模型和账号规则

到「连接设置」的「模型与账号规则」：

### 模型

可选 Astra、5.6 Sol、5.6 Terra，对应 `gpt-6-astra`、`gpt-5.6-sol`、`gpt-5.6-terra`。这是选择请求哪个模型，不是给账号增加权限。上游不提供的模型仍会失败，不会暗中替换为另一个名字。

保存后重启 Codex 或新建会话，避免旧任务继续沿用旧模型。不同模型有自己的 state，不共用一份采集结果。

### 账号规则

| 选择 | 用途 |
| --- | --- |
| 自动识别 | 根据当前登录请求里的套餐提示选择；提示缺失会说明当前采用的规则 |
| 个人 | 使用 10 块 / 通常 292 字符的经验规则 |
| Team | 使用 12 块 / 通常 332 字符的经验规则 |

Team 不应该一直追个人账号的 292。自动识别不确定时，你知道自己用的是 Team，就手动选 Team；不要把 `baseline_blocks` 乱调到“刚好通过”。

套餐提示只是本地筛选线索，不代替上游认证；不会仅凭一个 332 长度就宣称账号是 Team。312 / 356 不会冒充对应规则下的合格状态，长度也不是模型智力评分。

旧配置如果曾手动设置过非默认 `baseline_blocks`，自动模式可能保留旧规则。想回到新的账号规则，请在面板明确选个人或 Team，并核对会话显示的目标长度。

### 暂时采不到合格 state 时

- **严格等待：**正式请求不带不合格 state 继续走；没有可用值时返回本地 503，告诉你采集为什么没通过。
- **先正常使用：**首次 `setup` 没有明确策略时采用；明确选过严格的不会被启动覆盖。重新点接入按钮确认后也会采用，或者在这里主动选择。普通转发兜底开启后，没有合格值时不注入，正式请求只转发一次。不是把 312 改名为 292，也不是质量保证。

兜底和「关闭注入」不完全相同：兜底仍允许按规则采集，后续有合格值可以使用；关闭注入则不再采集或替换 state。官方通道普通转发时会保留 Codex 客户端本来携带的 state，不把“不由本服务注入”误做成“删掉客户端状态”；中转仍不接收官方 state。两者都不能解除 401 / 403 / 429 暂停。

## 确认 Codex 真的接上了

四个状态要分开：

| 面板上看到什么 | 说明 |
| --- | --- |
| 能登录面板 | 服务启动成功 |
| Codex 配置已接管 | 所选配置指向本地入口 |
| 请求次数增加 | 请求确实经过服务；出错请求也会计数 |
| 会话里已有可用 state | 本地采集筛选通过，不等于模型质量经过证明 |

看到「未接管」，先处理配置提示。若以 `--no-config` 启动，这是明确的只读模式：面板不会替你突破限制。停止后去掉该选项，用 `setup` 再启动。

接管后重启 Codex，新建会话发一条短消息。Codex 能回复但面板一直没请求，通常要核对启动实例、`CODEX_HOME`、profile，以及项目/任务级 provider 覆盖。不要靠连续发几十条消息判断。

会话列表和请求计数也不同：模型列表请求、被拦截的请求、已经过期的会话，都可能让“有请求但没有保留中的模型会话”成立。新版不再用空会话列表一口咬定“从未收到请求”。

## 开关显示怎么看

按钮显示的是**下一步动作**：

- 按钮「关闭注入」：当前开关是开。
- 按钮「开启注入」：当前开关是关。

旁边说明还会告诉你是否接管、是否走 API 中转。仅开关为开，不代表已经有 state 或 Codex 请求已经经过服务。旧版关→开后残留“已关闭注入”的说明是显示问题，本轮已针对它补了状态更新和测试。

中转 / 官方 API key 通道始终不注入官方 state，开关不会把它强行变成 ChatGPT 登录通道。

## 路由：固定一个出口，或恢复自动

进入「路由」，点「读取路由列表」。这可能重新下载订阅，但不调用模型。选一个出口做连接测试；200、401、403 都只说明这次无认证请求收到对应 HTTP 响应，不证明你的账号被接受或被拒绝。

固定出口后，采集和转发按该选择走；旧 state 会清空。自动模式按候选顺序采集，不是每条消息随机换 IP，更不是遇到错误就偷偷改成直连。

出口用稳定匿名 ID 区分，页面显示经过处理的标签和协议，不显示节点地址及密码。不过自定义标签也可能暴露个人备注，截图前仍要看一眼。

## CCS 和 profile 怎么配合

程序读取 Codex **当前选中的配置**，不读取 CCS 内部账号数据库。启动时可能只读所选 Codex 目录的 `auth.json` 判断认证类型，不把密钥返回给面板、不修改登录文件、不刷新登录。

- `env_key` 继续引用原变量名，Codex 进程需要能看到该环境变量。
- `requires_openai_auth = true` 不足以单独判断是官方登录；明确的 API key 认证仍按 API 通道处理。
- profile 要一致。本工具服务配置中的 `codex_profile` 和启动 Codex 时的 `--profile` 应指向同一个已有 profile。
- 项目、任务或额外启动参数可能覆盖全局配置，程序不会擅自清空它们。

最稳妥的顺序：**停止服务 → CCS 切换 → 再启动服务 → 重启 Codex。**

### 409 / 旧事务：优先保留当前配置

旧版把整份文件哈希当成接管状态，甚至改注释也会触发冲突。新版检查程序实际接管的连接与认证字段；无关改动保留，真实的上游或认证变化仍会暂停转发。

遇到 `codex_config_changed` 或 `unfinished config transaction`：

1. 在「连接设置」点 **「检查与修复配置」**，先看预览。
2. 通常选择 **「保留当前配置并重新接管」**，保留 CCS 刚选择的配置。
3. 无法安全保留时，按钮会被禁用或报错。只有确定要撤销后来的修改，才选 **「恢复接管前备份」**。
4. 确认后会先归档当前文件及恢复记录，再修改；文件在预览后改变则拒绝操作。
5. 成功后重启 Codex，新建会话。

「重新检查并接管」适合配置已经恢复正常、没有需要选择的冲突时使用，不是强制覆盖按钮。不要删除事务记录或备份来消除提示。

### 服务 JSON 损坏

用 `setup` 启动后会进入专门的只读修复面板：不加载坏配置里的代理、不接管 Codex、不请求模型。点「检查并重建服务配置」，确认后先备份旧 JSON，再生成关闭注入的默认配置。然后停止修复服务、重新 `setup`，填写自己的代理。

这会重建**本工具**配置，不会替你找回损坏文件中所有设置；原内容仍在本机备份。端口被其他程序占用、文件权限不足等情况仍需先处理，不承诺面板在任何系统错误下都能启动。

### Codex TOML 损坏

在「连接设置」展开 **「配置已经很乱，重新配置连接」**，点击 **「备份并重建连接配置」** 前，需要明确选择官方 ChatGPT 或 API key / 中转。中转还要确认 Responses 基础地址和已有密钥的环境变量名；输入的是变量名，不是密钥。

重建会完整保存原文件，但新的最小配置不会迁移原插件、MCP 和个性化设置。必要时从备份恢复；不要把重建当作每次启动的常规步骤。已有旧接管事务时先走上面的恢复流程。身份类型或上游不明确就停止；不能从坏 TOML 中猜出一个地址，再拿官方登录去试。

用 CCS 的，也可以先由 CCS 生成正确配置，再回到本工具接管。

## 采集失败后，什么时候能再试

会话里显示「重新采集」时，可以在检查好网络和账号规则后主动发起一次受限采集。按钮会显示冷却等待；已有可用值、正在采集、认证拒绝或限流期间不能用它强刷。采集会消耗实际模型额度，确认前看清提示。

它不是“换个按钮就绕过每轮次数限制”，也不会重放上一条生成。

## 远程上下文压缩

远程压缩不是 state 采集。本轮把两条请求分别处理：旧式 `POST /responses/compact` 与新版在 `POST /responses` 中携带 `compaction_trigger` 的压缩请求。它们不应因为没拿到 292 就先被采集拦住，也不能因压缩响应的 state 形状被当成普通生成结果拒绝。

官方 provider 的名称/能力声明也要保留正确，随意改成展示名称可能让客户端改走本地压缩。中转站则必须真正实现相应接口，不能通过冒充官方名称补出能力。

本轮真实 Sol 的 V2 压缩和压缩后回复已通过。直接访问真实上游的 V1 接口返回 404；V1→V2 兼容桥接尚在独立修复验证，不是遇到 404 后再自动重发。

**具体客户端和真实上游是否已验收，查[压缩验收项](issues-and-verification.md#p01-远程上下文压缩优先项)。普通聊天回复成功，不算压缩成功。**

## 出了问题，先看哪里

| 提示 | 处理方法 |
| --- | --- |
| 口令错误 | 使用本次启动终端的口令；旧口令不会自动续期 |
| 有请求正在处理 | 等回复结束再保存设置，不连点重试 |
| 来源解析失败 / 没有节点 | 检查格式、下载标识和过滤条件；也可先用本地代理 |
| 出口连接失败 | 检查代理软件、端口和节点；连接测试不验证模型权限 |
| 目标长度与账号不符 | 核对自动识别提示，手动选个人或 Team |
| `state_unavailable` | 查看采集诊断：网络、封装、响应不完整、形状、时间、冷却或上游拒绝 |
| `state_shape_changed` | 正式请求可能已消耗额度，不会自动重放 |
| 415 / 不支持请求编码 | 本轮补了官方客户端 gzip/zstd 解码；先确认运行版本，不能把本地 415 当成上游拒绝 |
| HTTP 200 但流内失败 | 200 只说明 HTTP 请求建立了；看模型容量、响应失败或明确额度错误。容量不足不等于 HTTP 429，不要按正文猜错误 |
| 上游 503 / 502 | 检查上游和出口，区别于本地采集失败 |
| 401 / 403 | 在 Codex 或服务提供方处理登录、访问权限，不换 IP 继续撞 |
| 429 | 等额度或速率恢复；换出口、模型或关闭注入都不是重置方法 |
| `Encrypted content...` | 可能涉及上游密文或会话链，保留工作后排查，不自动删除上下文 |

去「遇到问题」点 **「下载脱敏诊断」**，或执行 `ccodex-sleep-state doctor`。诊断不包含提示词、登录凭据、订阅地址、完整 state。原始数据目录里的配置和备份不等于脱敏报告，别一起发出去。

## 改完什么时候生效

- 开关注入：影响后续请求，正在进行的回复不强制中断。
- 面板来源、路由、账号规则：在管理操作允许后生效，不需要重启服务；切换出口不复用旧 state。
- 默认模型：保存后重启 Codex 或新建会话，让客户端采用新选择。
- 编辑器直接改服务 JSON：停止后重启，程序不会覆盖外部改动。
- CCS/provider/profile 改动：推荐先停止服务，选好配置再启动。
- 完全退出接管：终端 Ctrl+C，确认恢复完成，再重启 Codex。

# 管理面板：不用再对着 JSON 猜该填哪

面板和转发服务是同一个程序、同一个端口。没有额外的数据库、Web 服务或云端账号。它只允许本机访问，不是给公网部署的管理后台。

## 打开面板

运行 `serve` 后，从终端复制“管理面板”地址和“管理口令”。默认地址是：

```text
http://127.0.0.1:17841/admin/
```

浏览器粘贴口令进入即可。不要把地址里的 `127.0.0.1` 换成局域网 IP；如果你改过监听端口，以终端输出为准。

口令只在当前浏览器标签页的会话存储中保存，不通过网址参数传递。服务重启后旧口令失效，重新复制一次。它能修改本工具的配置，所以截图发群前记得遮住。用完可以点退出。

## 概览：先确认现在是什么模式

- **官方 ChatGPT + 开启注入：** 需要采到符合规则的 state 才转发生成请求。采集会用到实际模型额度。
- **官方 ChatGPT + 关闭注入：** 不再采集或注入 state，但请求仍从本地服务、经你选择的出口发送。不是卸载，也不是恢复原配置。
- **API / 中转：** 只做普通转发，注入开关禁用；不向官方后端采票，不要求 292。

关闭注入不会增加额度，也不会清除已经收到的 401、403、429 暂停。正在执行的请求不会被偷偷切到另一种模式；管理操作遇到忙碌提示，等这次回复结束再试。

刚启动时会话列表为空是正常的。重新打开 Codex 并发出请求后，列表才会出现会话。若一直为空，检查 Codex 是否仍在用别的 provider、profile 或项目级覆盖。

## 订阅与代理：选一种来源

| 你手里有什么 | 选择什么 | 填什么 |
|---|---|---|
| 本机可以直接访问上游 | 直连 | 不用填地址 |
| 正在运行的代理软件 | 本地代理 | 它实际提供的 HTTP / HTTPS / SOCKS5 地址与端口 |
| 订阅服务给的链接 | 订阅链接 | 完整链接，不是订阅网站首页 |
| 下载到本机的节点文件 | 本地订阅文件 | 该文件的完整路径 |
| 本机程序提供的订阅接口 | 订阅链接 | `http://127.0.0.1:端口/路径` 形式的本机链接 |

远程订阅必须用 HTTPS。本地 HTTP 订阅只接受字面值回环 IP，例如 `127.0.0.1` 或 `[::1]`；不要用 `localhost` 代替。订阅文件只读，不修改原文件；支持 Clash/Mihomo 的顶层 `proxies`、逐行 URI 和 Base64 URI 列表。

“测试”会下载或读取订阅、解析节点并构建出站配置。**它不连接模型、不消耗模型额度，也不代表节点已经连通。** 测试通过后，还要点应用；应用会备份旧服务配置，替换整组出口来源，清掉旧 state。需要同时保留多个来源时，用 JSON 配置，见[代理教程](proxies.md)。

面板保存的订阅链接或代理地址可能含密码，会写进本机配置和配置备份。不要把这些文件同步到公开仓库。想用环境变量保存秘密，可以按[命令行配置方法](proxies.md#用订阅链接)操作。

高级选项里的下载标识、协议和排除关键词按需填写，不必为了“看起来更完整”全填上。节点名称筛选不是地理位置检测。

## 路由：先测试连接，再决定是否固定

1. 点加载出口，列出当前来源解析出的匿名出口 ID。
2. 点测试连接。程序通过这个出口向所选上游的模型列表接口发一个**不带登录信息**的请求。
3. 收到 HTTP 响应说明这次网络链路有回应；401 / 403 在这个无认证测试里并不说明你的账号被拒。200 也不证明能采到 state。
4. 如果想只用一个出口，点固定。想恢复候选池，就选自动。

ID 用于区分出口；本地管理页可以显示经过处理的订阅节点名称和协议，方便选择，但不显示节点地址和密码。截图分享前仍请检查名称里是否有自己的备注。稳定匿名 ID 能避免订阅换了排序后指向另一个节点；节点配置本身变化后，仍可能需要重新选择。

固定出口会清掉旧 state；开启注入时，后续采集只尝试这个出口，转发使用与 state 对应的出口。关闭注入或走中转时，也使用选定的出口。自动模式不等于每条请求随机换 IP，更不表示出错就悄悄直连。

遇到 401 / 403 / 429 暂停时，应用来源和切路由会被拒绝。先处理登录、权限或等待限流恢复，别把换节点当作重置额度。

## CCS 和 profile 怎么配合

程序接管的是 **Codex 当前使用的配置文件**，不是 CCS 的内部数据库。先在 CCS 选好 provider，再退出 Codex、启动本服务，最后重新打开 Codex。

启动时会读取所选 provider 的上游地址及认证方式。读取配置不等于把密钥返回给面板；认证头来自后续 Codex 请求。启动时会只读所选 Codex 目录的 `auth.json` 来判断认证类型，只返回类型，不返回密钥，也不修改文件或刷新登录。

- `env_key` 仍引用原来的变量名，服务不会替你创建 API key。Codex 进程需要能看到对应环境变量。
- 官方 API key 对应 API 通道，不是 ChatGPT 订阅登录。
- `requires_openai_auth = true` 不能单独决定它是官方登录；当 `auth.json` 明确是 `OPENAI_API_KEY` 认证时，即使 `requires_openai_auth = true`，中转仍按 API 通道判断。配置含义不明确或有泄漏风险时，宁可报错，不把官方登录凭据试着发给中转。
- profile 要一致。在本工具的 JSON 中设置 `"codex_profile": "work"` 后，Codex CLI 也要用 `codex --profile work` 启动。`work` 是示例，请换成自己已有的 profile 名称。没有使用 profile 就留空。
- 任务级、项目级及其他启动参数可能覆盖全局配置；本服务不会清空它们。接管后仍没收到请求，先检查这些覆盖项。

需要切换时按这个顺序：**停止本服务并恢复配置 → CCS 切换 → 再启动本服务 → 重启 Codex。** 运行中发现配置被改动，会拒绝继续转发，而不是猜测新的凭据该发到哪。

## 出了问题，先看哪里

| 提示 | 处理方法 |
|---|---|
| 管理口令错误 | 确认是当前服务终端的口令；重启后的旧口令不能用 |
| Codex 正在处理请求 | 等当前回复结束，再保存或切换配置 |
| 没有节点 / 来源解析失败 | 检查订阅格式、下载标识和过滤条件，或先用本地代理 |
| 出口连接失败 | 确认代理软件启动、端口正确；有响应不等于有合格 state |
| 固定出口不存在 | 重新加载路由并选择，或切回自动 |
| `state_unavailable` | 本地没采到合格 state；看探测日志的 `result`、`state_blocks`、`expected_blocks`，等冷却或明确关闭注入 |
| `state_shape_changed` | 正式请求已发出，上游可能已经计费；不会自动重放 |
| 上游 503 | 上游服务未能处理请求，不是本地 state 拦截；响应头标为 `X-Sleep-State-Error-Source: upstream` |
| 配置被 CCS 或其他程序修改 | 停止服务，保留当前文件和备份，核对后重新启动 |
| 恢复冲突 | 不要删事务记录；先备份当前文件、核对差异，再恢复。见 [Windows 恢复步骤](windows.md#停止与恢复) |

来源加载失败或恢复冲突时，面板仍可显示问题；但 JSON 语法错误、非法监听地址等启动前校验失败，需要先在文件里修好。面板不是一个无论配置多坏都能启动的安装器。

## 修改什么时候生效

- **面板开关注入：** 保存后影响后续请求。
- **面板应用来源、固定路由：** 在没有前台请求执行时切换，不需要重启；旧 state 清空。
- **编辑器直接修改 JSON：** 停止后再启动，不会自动监控文件。
- **CCS / Codex provider 或 profile 改动：** 先停止服务，选好配置再重新启动。
- **想完全退出接管：** 终端 Ctrl+C，确认恢复完成，再重启 Codex。只关闭浏览器不会停止服务。
